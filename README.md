# RAIN — أول مخ حقيقي محلي

Rain الحين عنده موديل ذكاء فعلي يشتغل على جهازك بالكامل، بدون إنترنت وقت
المحادثة. كل شي بين الواجهة والمخ يصير على جهازك فقط (`127.0.0.1`) — ما
يطلع شي بره جهازك.

نستخدم **Rain.exe** — ملف تنفيذي واحد بس (مبني بتقنية llamafile) فيه
محرك التشغيل وموديلك المدرّب مدمجين مع بعض. ما فيه برنامج منفصل تثبته،
وما فيه ملف موديل منفصل تدير مساره — دبل كليك على `Rain.exe` وخلاص،
يفتح سيرفر محلي جاهز.

## مكونات المشروع

```
rain_app/
├── app.py           ← السيرفر: يوصل الواجهة بـ Rain.exe
├── rain_ui.html      ← الواجهة (تصميم Jarvis)
├── requirements.txt  ← مكتبة Flask بس
├── Rain.exe          ← الموديل + محرك التشغيل، ملف واحد (تسويه بنفسك، شوف تحت)
└── README.md         ← هذا الملف
```

## خطوة 1: جهّز Rain.exe (مرة وحدة بس)

1. حمّل أداة llamafile الأساسية (النسخة الفارغة بدون موديل) من صفحتها
   على GitHub
2. باستخدام أداة `zipalign` اللي تجي معاها، ادمج ملف `rain-cyber.gguf`
   حقك جوا الملف التنفيذي نفسه
3. غيّر اسم الملف الناتج لـ`Rain.exe`
4. حطه بنفس مجلد `rain_app`

(لو احتجت تفاصيل أكثر لهالخطوة، اسألني بالمحادثة وأعطيك الأوامر بالضبط
حسب جهازك.)

## خطوة 2: شغّل Rain.exe

دبل كليك على `Rain.exe` — تفتح نافذة CMD وتفضل شغالة بالخلفية (لا
تسكرها). هذا يشغّل سيرفر محلي على المنفذ `8080`.

## خطوة 3: ثبّت Flask وشغّل Rain

جوه مجلد `rain_app`:

```
pip install -r requirements.txt
python app.py
```

افتح المتصفح على:

```
http://127.0.0.1:5000
```

اكتب لـ Rain أي شي — بيرد عليك فعلياً من الموديل المحلي (أول رد ممكن
ياخذ وقت أطول شوي).

## لو صار خطأ

- **"Rain.exe مو شغّال"** — تأكد إن نافذة CMD حقت `Rain.exe` لسا مفتوحة
  وما قفلتها بالغلط
- **خطأ "illegal instruction" لما تشغّل Rain.exe** — نسخة llamafile
  اللي حملتها ما تتوافق مع معالجك، جرب نسخة ثانية من صفحة الإصدارات

## ملاحظات

- **السرعة:** على معالج قديم بدون GPU، الرد ممكن ياخذ من 10-30 ثانية. طبيعي لموديل يشتغل على CPU.
- **الخصوصية:** ما فيه اتصال إنترنت وقت المحادثة — كل شي محلي 100%.
- **الشخصية:** عدّلها من `SYSTEM_PROMPT` داخل `app.py`.

## أدوات Bug Bounty

Rain الحين عنده أدوات استطلاع (recon) أساسية يقدر يستخدمها لمّا تطلب منه
يفحص هدف معيّن، موجودة بملف `tools.py`:

- **dns_lookup** — عناوين IP لدومين (سلبي ✅)
- **http_headers** — رؤوس استجابة HTTP لرابط (سلبي ✅)
- **subdomains_crtsh** — سب-دومينات معروفة عن طريق سجلات الشهادات العامة (سلبي ✅)
- **port_scan** — فحص منافذ شائعة مفتوحة (نشط ⚠️)

**مهم جداً:** استخدم هذي الأدوات بس على أهداف تملكها أو مصرح لك تفحصها
رسمياً (مثلاً ضمن نطاق برنامج bug bounty). Rain مبرمج يسأل عن التصريح
قبل الأدوات النشطة (⚠️)، لكن المسؤولية القانونية والأخلاقية عليك كمستخدم
— فحص هدف بدون إذن ممكن يكون جريمة حتى لو التقنية نفسها "استطلاع بسيط".

لإضافة أداة جديدة: افتح `tools.py`، اكتب دالة بايثون جديدة، وسجّلها
بقاموس `TOOLS` بالأسفل — Rain بياخذ وصفها تلقائياً ويعرف يستخدمها.

## الخطوة الجاية (مو الحين)

لما يصير عندك جهاز/سيرفر أقوى، نقدر ندرّب موديل Rain أكبر وأقوى ونحطه
بنفس طريقة `Rain.exe` — ملف واحد، بدون تعقيد.

# 🌧️ Rain Engine

**محرك ذكاء اصطناعي يُبنى من الصفر باستخدام لغة Rust.**

يهدف مشروع Rain Engine إلى تطوير محرك مستقل لتنفيذ الشبكات العصبية وتوليد النصوص، مع بناء المكونات الأساسية من الصفر بدلًا من الاعتماد على محرك استدلال جاهز.

يستهدف المشروع نظام Windows في البداية، مع تصميم يسمح بإضافة دعم Linux مستقبلًا.

> **حالة المشروع:** في المراحل الأولى من التطوير. المكونات الأساسية للاستدلال لم تُنفّذ بعد.

## 🎯 رؤية المشروع

إنشاء محرك ذكاء اصطناعي مستقل يمنحنا تحكمًا كاملًا في المكونات الأساسية، بدءًا من العمليات الرياضية وإدارة الموترات، وصولًا إلى تحميل النماذج وتشغيل الشبكات العصبية وتوليد النصوص.

يبدأ المشروع بتجارب صغيرة قابلة للاختبار، ثم يتطور تدريجيًا ليصبح أساسًا لتشغيل النماذج اللغوية وتطوير نماذج خاصة بمشروع Rain.

## 🧠 المبادئ الأساسية

- **البناء من الصفر:** تطوير العمليات الحسابية الأساسية وتنفيذ الشبكات العصبية دون الاعتماد على محرك استدلال جاهز.
- **لغة Rust:** الاستفادة من الأمان وإدارة الذاكرة والأداء.
- **المعالج أولًا:** البدء بالتنفيذ باستخدام CPU قبل التفكير في تسريع العمليات عبر العتاد.
- **كفاءة الذاكرة:** مراعاة الأجهزة ذات الموارد المحدودة وتقليل الحجوزات غير الضرورية.
- **التوافق بين الأنظمة:** تطوير Windows أولًا مع التخطيط لدعم Linux.
- **الاختبار المستمر:** التحقق من صحة العمليات الرياضية وتحميل الملفات باستخدام اختبارات آلية.
- **التصميم المعياري:** فصل المحرك الرياضي عن نظام النماذج وواجهة التشغيل وتوليد النصوص.

## 🏗️ البنية الهندسية المخططة

```text
Rain Engine
├── واجهة سطر الأوامر (CLI)
├── النواة الأساسية (Engine Core)
│   ├── الإعدادات
│   ├── معالجة الأخطاء
│   └── إدارة التنفيذ
├── محرك الموترات (Tensor Engine)
│   ├── تخزين البيانات
│   ├── عمليات المصفوفات
│   └── العمليات الرياضية
├── نظام النماذج (Model System)
│   ├── تنسيق Rain الخاص
│   ├── تحميل النماذج
│   └── التحقق من سلامة الملفات
├── الشبكات العصبية (Neural Network)
│   ├── Embeddings
│   ├── الطبقات الخطية
│   ├── التطبيع
│   ├── آلية الانتباه
│   └── طبقات Transformer
└── توليد النصوص (Text Generation)
    ├── تقسيم النص إلى رموز
    ├── اختيار الرموز
    └── إدارة سياق المحادثة
```

هذه البنية تمثل الخطة المستقبلية، ولا تعني أن جميع مكوناتها موجودة أو تعمل حاليًا.

## ⚙️ قيود التطوير

يركز المشروع في مراحله الأولى على صحة النتائج وبساطة التجارب قبل تحسين الأداء.

سيبدأ التنفيذ باستخدام المعالج والعمليات الرياضية الأساسية، مع مراعاة حدود الذاكرة والأجهزة القديمة. وقد تتجاوز النماذج اللغوية الكبيرة وعمليات التدريب قدرات هذه الأجهزة.

تسريع GPU والتكميم المتقدم وتحسين الاستدلال مجالات مستقبلية، وليست ميزات مكتملة حاليًا.

## 🔐 الأمان والموثوقية

- التحقق من ملفات النماذج قبل تحميلها.
- فحص أبعاد الموترات ومنع تجاوز حدود الأعداد.
- تجنب حجوزات الذاكرة غير المحدودة.
- التعامل مع المدخلات غير الصحيحة بأمان قدر الإمكان.
- اختبار قراءة الملفات والعمليات الرياضية بصورة مستقلة.

## 📌 الحالة الحالية

Rain Engine مشروع تجريبي قيد التطوير.

لا يدّعي المشروع حاليًا امتلاك نموذج لغوي جاهز، أو نظام توليد نصوص متكامل، أو تسريع عبر GPU، أو منظومة تدريب مكتملة. ستُضاف هذه الإمكانات تدريجيًا بعد تنفيذها واختبارها.
